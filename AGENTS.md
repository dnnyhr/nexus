# NEXUS — instrucciones de trabajo

- Repo activo único: `dnnyhr/nexus`. `origin` apunta a NEXUS.
- Leer `docs/mision-1/README.md`, contrato y prompt propio antes de editar.
- Comunicación en español, breve y directa. Código y términos técnicos exactos.
- No añadir comentarios de código salvo pedido; conservar comentarios existentes pertinentes.
- Preservar Modo libre, perfil, controles táctiles, pantalla completa, manifest y cambios ya integrados.
- Misión 1 es integración incremental; no añadir React, Tailwind, segundo package.json ni motor HailMary en producción.
- No añadir dependencias ni modificar lockfile para este alcance.
- Un motor de misión comparte primitivas del juego. Proyección y partida usan mismas reglas.
- `src/engine/types.ts` es contrato común. Cambios coordinados por integrador antes de usarlos.
- Cinco roles: integrador, A motor, B preparación/barra, C comandante/informe, D QA. Propiedad de archivos en contrato.
- Cada ejecutor usa worktree propio dentro de `.worktrees/`; solo integrador usa checkout principal. Worktrees comparten una repo Git.
- No cambiar de rama en checkout de otro agente. No hacer `git pull` indiscriminado ni merge automático desde `main`.
- Leer referencias HailMary desde `docs/referencias/hailmary/`; no importar esas fuentes en runtime ni volver a depender del checkout HailMary.
- Nada de mocks de producción ni APIs falsas para declarar integración terminada. B/C esperan contrato y motor reales para validar flujo completo.
- Tests deben comprobar comportamiento; no cambiar expectativas o datos solo para ocultar fallos.
- Separar tests/build de QA de navegador, teléfono, instalación y offline.
- Commits locales de implementación: al ejecutar encargo del agente, pequeños y limitados a su carril. Esta preparación documental no creó commits.
- Push, PR remoto, merge a main y deploy requieren instrucción explícita. Permisos genéricos de prompts originales no se trasladan automáticamente.
- No borrar HailMary, partidas, ramas ni trabajo concurrente. No force push ni reset destructivo.
- No añadir secretos, config privada, sesiones o telemetría.
